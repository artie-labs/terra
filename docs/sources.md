## Postgres 16

| key | URL | the sentence that matters |
| --- | --- | --- |
| pg-lr-overview | https://www.postgresql.org/docs/16/logical-replication.html | "Logical replication of a table typically starts with taking a snapshot of the data on the publisher database and copying that to the subscriber." Then "the changes on the publisher are sent to the subscriber as they occur in real-time." |
| pg-lr-publication | https://www.postgresql.org/docs/16/logical-replication-publication.html | "A published table must have a replica identity configured in order to be able to replicate UPDATE and DELETE operations"; "If a table without a replica identity is added to a publication that replicates UPDATE or DELETE operations then subsequent UPDATE or DELETE operations will cause an error on the publisher." |
| pg-lr-subscription | https://www.postgresql.org/docs/16/logical-replication-subscription.html | "Columns of a table are also matched by name. The order of columns in the subscriber table does not need to match that of the publisher. The data types of the columns do not need to match, as long as the text representation of the data can be converted to the target type. [...] The target table can also have additional columns not provided by the published table. Any such columns will be filled with the default value as specified in the definition of the target table." Also: "The schema definitions are not replicated, and the published tables must exist on the subscriber." |
| pg-lr-restrictions | https://www.postgresql.org/docs/16/logical-replication-restrictions.html | "The database schema and DDL commands are not replicated. [...] Subsequent schema changes would need to be kept in sync manually." "Sequence data is not replicated." "When the schema is changed on the publisher and replicated data starts arriving at the subscriber but does not fit into the table schema, replication will error until the schema is updated. In many cases, intermittent errors can be avoided by applying additive schema changes to the subscriber first." |
| pg-lr-conflicts | https://www.postgresql.org/docs/16/logical-replication-conflicts.html | "If incoming data violates any constraints the replication will stop. This is referred to as a conflict." "A conflict will produce an error and will stop the replication; it must be resolved manually by the user. Details about the conflict can be found in the subscriber's server log." Resolution: change the subscriber so the data fits, or skip the transaction with `ALTER SUBSCRIPTION ... SKIP` or `pg_replication_origin_advance()`. "When replicating UPDATE or DELETE operations, missing data will not produce a conflict and such operations will simply be skipped." |
| pg-createpublication | https://www.postgresql.org/docs/16/sql-createpublication.html | FOR ALL TABLES "Marks the publication as one that replicates changes for all tables in the database, including tables created in the future." |
| pg-createsubscription | https://www.postgresql.org/docs/16/sql-createsubscription.html | copy_data: "Specifies whether to copy pre-existing data in the publications that are being subscribed to when the replication starts. The default is true." "this command normally creates a replication slot on the publisher." disable_on_error: "whether the subscription should be automatically disabled if any errors are detected [...] The default is false." |
| pg-altersubscription | https://www.postgresql.org/docs/16/sql-altersubscription.html | REFRESH PUBLICATION: "Fetch missing table information from publisher. This will start replication of tables that were added to the subscribed-to publications since CREATE SUBSCRIPTION or the last invocation of REFRESH PUBLICATION." |
| pg-altertable | https://www.postgresql.org/docs/16/sql-altertable.html | "Adding a column with a volatile DEFAULT or changing the type of an existing column will require the entire table and its indexes to be rewritten." "When a column is added with ADD COLUMN and a non-volatile DEFAULT is specified, the default is evaluated at the time of the statement and the result stored in the table's metadata. [...] In neither case is a rewrite of the table required." RENAME: "There is no effect on the stored data." DROP COLUMN "does not physically remove the column, but simply makes it invisible to SQL operations." REPLICA IDENTITY DEFAULT "Records the old values of the columns of the primary key, if any"; FULL "Records the old values of all columns in the row." |
| pg-altertype | https://www.postgresql.org/docs/16/sql-altertype.html | "If ALTER TYPE ... ADD VALUE (the form that adds a new value to an enum type) is executed inside a transaction block, the new value cannot be used until after the transaction has been committed." |
| pg-toast | https://www.postgresql.org/docs/16/storage-toast.html | "The TOAST management code is triggered only when a row value to be stored in a table is wider than TOAST_TUPLE_THRESHOLD bytes (normally 2 kB)." |

Navigation taken from https://artie.com/docs and its machine index https://artie.com/docs/llms.txt.

| key | URL | the sentence that matters |

| artie-docs-index | https://artie.com/docs/llms.txt | Index of every docs page. Lists 17 destination pages: BigQuery, ClickHouse, Databricks, Delta Lake (S3), Google Cloud Storage, S3 Tables (Iceberg), REST Catalog (Iceberg), Microsoft SQL Server, MotherDuck, MySQL, Oracle, PostgreSQL, Databricks Lakebase, Redis, Redshift, S3, Snowflake. |
| artie-postgres | https://artie.com/docs/sources/postgresql | Setup: "Create dbz_publication publication on the primary database" with `CREATE PUBLICATION dbz_publication FOR ALL TABLES;` and "We recommend enabling publications for all tables." Schema: "DDL changes such as ALTER TABLE ... ADD COLUMN do not appear as discrete events in the PostgreSQL WAL." Artie uses "lazy schema evaluation," so "the new column will not appear in the destination until a DML event occurs on that table." TOAST: "if the column value has not changed, the column value will not be included in WAL if the table's replica identity is set to default." "Artie has automatic detection built-in to detect an unchanged TOAST column and will conditionally replicate this into the target database." "Our built-in process will detect if an incoming CDC event has an unchanged TOAST column and will not update the column value in the target database." "We are able to do all of this without having to increase your table replica identity." Heartbeats: "You'll want to enable heartbeats to prevent your replication slot from overflowing if you have an idle database." Idle sessions: avoid lingering idle transactions by "setting idle_in_transaction_session_timeout." Tables without a primary key: "Set the table's replica identity to FULL" and configure override primary keys. |
| artie-postgres-troubleshooting | https://artie.com/docs/sources/postgresql/troubleshooting | "A growing replication slot means PostgreSQL is retaining WAL segments that have not yet been consumed." "If the slot size keeps increasing and never decreases, the retained WAL can eventually exhaust disk space." "Enable heartbeats in Artie to periodically advance the replication slot." |
| artie-schema-evolution | https://artie.com/docs/guides/artie/schema-evolution | "We automatically create tables in your destination if they don't exist"; "We detect and add new columns automatically"; "For safety reasons, columns are not automatically dropped from destination tables." With "Enable hard deletes for columns": "When a column is deleted from the source, the first row that omits this column marks it for potential removal", "We then monitor CDC events for 4 hours to ensure the column is consistently omitted", "Only after this verification period will we proceed with dropping the column." The reconciliation job "does not rename columns or change the type of an existing destination column." Nothing about enum values, widening or narrowing. |
| artie-typing | https://artie.com/docs/guides/artie/arties-typing-library | "We preserve the exact numeric type from your source (Postgres, MySQL, or MongoDB)." "We maintain JSON objects exactly as they appear in your source, with no flattening or transformation." "Artie uses the destination schema as a source of truth and maintains that type to ensure consistency." "If Artie encounters a type conversion that could lead to data loss or errors, we'll" raise an error and notify. Numeric without precision: "we will create this type as a string equivalent column so that we do not have to trade off data precision." Enums are not mentioned. |
| artie-system-columns | https://artie.com/docs/pipelines/system-columns | `__artie_delete` (BOOLEAN): "true if the row was deleted in the source database", enabled by the soft delete columns setting; "Instead of removing deleted rows, Artie flags them so you can retain the data." `__artie_operation` values r, c, u, d. `__artie_updated_at` and `__artie_db_updated_at` (TIMESTAMP_TZ, history mode). `__artie_only_set_delete` (S3 only). `__artie_full_source_table_name`, `__artie_source_metadata` (table settings). |
| artie-tables | https://artie.com/docs/pipelines/tables | "Skip deletes: When enabled, Artie will skip processing deletes." New source tables: "Artie checks for new source tables every weekday at 6am PT." Valid tables "are added to the pipeline and deployed automatically; tables that cannot be validated are not added." Column inclusion: "you'll need to manually add any new source columns to your inclusion list as they appear." |
| artie-schema-changes | https://artie.com/docs/monitoring/schema-changes | Notifications cover "Tables added", "Tables removed", "Tables changed" with "Columns added", "Columns removed", "Columns altered, including data type, default value, and not-null constraint". "They do not change the destination schema." With "Automatically apply supported schema changes" enabled, a reconciliation job "runs daily between 7:00 and 8:00 AM Pacific Time." |
| artie-destination-postgres | https://artie.com/docs/destinations/postgres | Service account "has the ability to create on the database and is the owner of all the schemas you plan to sync into": `GRANT CREATE ON DATABASE your_database TO artie; ALTER SCHEMA schema_name OWNER TO artie;` Artie lowercases destination column names. |
